# Exact apples-to-apples MLP comparison

This is a new, isolated 125-run cohort. It reproduces the original CIFAR-10
MLP notebook and adds quadratic-early and quartic-early profiles without
changing the already frozen scale-transfer run.

## Scientific contract

Every arm uses the same original recipe:

- unstratified `RandomState(0)` draws of 5,000 CIFAR-10 training images and
  then 5,000 test images;
- ReLU MLP with depth 6, width 256, `sigma_w_sq=1.98`, and
  `sigma_b_sq=0.02`;
- mean dropout 0.10 and cap 0.20;
- 75 epochs, batch size 100, AdamW learning rate `1e-4`, weight decay `1e-7`,
  and `CosineAnnealingLR(T_max=75, eta_min=1e-7)`;
- paired seeds 42 through 66 (25 seeds);
- the notebook's single global PyTorch RNG stream for model construction,
  minibatch permutations, and dropout;
- H100 autocast and plain backward/optimizer steps, as in the notebook;
- test evaluation each epoch, with final-epoch test cross-entropy as the
  primary comparison endpoint.

The five profiles are uniform, the legacy early-linear and early-step arms,
and the new early-quadratic and early-quartic arms. The new power profiles use
cell-center layer positions, exact discrete mean 0.10, and cap 0.20. Step early
is the prespecified legacy comparator for the new profiles because it is the
best early reference in the frozen saved result; it is not selected from the
rerun outcomes. Linear early and step early are both still reported
descriptively.

The machine-readable `preflight.json` is generated by [`run.py`](run.py)
records every invariant, all five layerwise schedules, the two frozen subset
hashes, and the saved-original artifact hash before training begins.

### Manuscript-settings correction

The executable notebook and saved artifact establish that the original main
MLP run used **75 epochs, 25 seeds, and batch size 100**. Any stale manuscript
prose, caption, or prior summary that gives a different value should be
corrected to these settings. The exact rerun does not reinterpret or silently
modernize them.

This cohort must not be pooled with the remaining 710 scale-transfer trials.
Those trials are a separate internally paired study using a stratified
4,000/1,000 train/validation split, batch size 75, independent named RNG
streams, validation-only selection, and final-only test access. Compare
absolute endpoints only within their own protocol.

## Historical Big-step extension

The paper's largest reported ReLU gain (35.4%) used the historical **Big
step (1/3)** profile rather than the cap-0.20 step schedule: at depth six and
mean dropout 0.10, it is `(0.30, 0.30, 0, 0, 0, 0)`. Consequently, it matches
the mean budget but exceeds the cap used for the quadratic/quartic cohort.
It must be recorded as a separate 25-seed, paired historical benchmark—not as
a cap-matched primary comparison that can decide whether Big step is better
than quadratic.

Create a distinct source snapshot and plan containing only this profile:

```bash
export BIG_STEP_SNAPSHOT="$PWD/../snapshots/legacy-bigstep-new-cohort"
python experiments/legacy/run.py snapshot-source \
  --output "$BIG_STEP_SNAPSHOT" \
  --slurm-script experiments/legacy/slurm/run_h100.sbatch \
  --profile big_step
```

On Bridges, plan with `--profile big_step`, then submit the normal four-way
array. The separate run directory ensures its `.30` peak and source hash can
never be silently merged into the cap-0.20 cohort.

## Submit four independent H100 shards

```bash
sbatch -A phy260030p \
  --array=0-3%4 \
  --output="$RUN_DIR/logs/slurm-dropout-legacy-%A_%a.out" \
  --export=ALL,PROJECT_DIR="$PROJECT_DIR",RUN_DIR="$RUN_DIR",VENV_DIR="$VENV_DIR",DATA_ROOT="$DATA_ROOT",NUM_SHARDS=4 \
  "$PROJECT_DIR/experiments/legacy/slurm/run_h100.sbatch"
```

The four array elements can land on different nodes. Each processes 31 or 32
manifest rows and requests one H100 for up to two hours. Repeating the same
submission is safe: a completed result is reused only after its trial hash,
data hash, and source-provenance hash all match.

Optional canary filters `FILTER_PROFILE` and `FILTER_SEED` select real frozen
rows. They do not create a different treatment or manifest.

## Monitor, verify, and analyze

```bash
squeue -u "$USER" -t R,PD -o "%.18i %.24j %.10P %.2t %.10M %.10l %R"
python "$PROJECT_DIR/experiments/legacy/run.py" status --run-dir "$RUN_DIR"
python "$PROJECT_DIR/experiments/legacy/analyze.py" --run-dir "$RUN_DIR"
```

Analysis requires all 125 trials. It writes:

- `legacy_profile_summary.csv`;
- `legacy_paired_comparisons.csv`;
- `legacy_reference_reproduction.csv`;
- test-loss/accuracy learning curves in PNG and PDF;
- saved-versus-rerun reference plots in PNG and PDF;
- `legacy_analysis.json` with artifact hashes and interpretation guardrails.

The four prespecified primary contrasts are quadratic and quartic versus
rerun uniform and versus prespecified step early. The tables report paired
bootstrap 95% intervals, exact 25-pair sign-flip p-values, and Holm correction
over those four loss contrasts. Compute-to-baseline accuracy is explicitly a
diagnostic because the exact legacy recipe examines test accuracy every epoch.
